# Trust Graph Artifacts v0.13.0

TGA v0.13.0 is an additive executable-governance release that makes action-specific authority and collective-authority lifecycle change directly testable. It consolidates the material execution work completed after v0.12.1 and prepares exact evidence for the separately governed TSMS Stack 2026.2 successor baseline.

## Highlights

- enforces authority at the exact material commitment rather than treating identity, signature, or a broad mandate as sufficient;
- binds current scope, lifecycle state, required approvals and the attempted action into the executable authority decision;
- adds negative cases proving reputation and prior runtime success cannot expand authority;
- exercises collective/composite authority with membership, threshold and exercise-rule freshness;
- rejects stale collective-authority evidence after material governance change;
- preserves historical verification without promoting it to current authorization.

## Authority-at-commitment execution

The runtime authority envelope now distinguishes:

```text
identity / authentication
        ≠
general mandate
        ≠
authority for this exact material commitment
```

A valid execution path requires the exact action to be within current authority, satisfy applicable scope/limits, remain unexpired and unrevoked, and carry required approval evidence. Missing or indeterminate authority evidence remains non-success.

## Composite-authority lifecycle execution

The release adds deterministic pressure cases for collective authority, including a valid 2-of-3 act and rejection of insufficient participation. More importantly, it proves that previously valid evidence becomes stale for current authorization when membership, threshold, or exercise rules materially change.

This behavior is cryptosystem-neutral. TGA executes the governance consequence; it does not define a threshold-signature protocol.

## TSMS alignment

TGA v0.13.0 consumes:

- TSMM v0.25.0 as canonical semantic authority;
- TIS v0.15.0 as portable-contract authority.

TGA remains authoritative only for project-local executable governance compositions, implementation patterns and negative tests. A green local execution cannot override unknown or incompatible TSMM/TIS state.

The immutable TSMS 2026.1 receipt remains historical evidence. v0.13.0 is a candidate component input to the successor TSMS 2026.2 receipt and does not independently create stack compatibility.

## Compatibility

v0.13.0 is additive relative to v0.12.1. Existing artifact families remain valid. Consumers that adopt the new action-specific authority or collective-authority lifecycle patterns should bind the corresponding TSMM semantics and TIS contracts explicitly.

## Validation

The canonical gate is:

```bash
make validate
```

It exercises repository conformance, authority envelopes, delegation lineage, receipts, TIS alignment, artifact assurance cases, TSMS golden-path checks, action-specific authority cases, collective-authority invalidation cases, documentation integrity, repository governance, and release/publication consistency.

## Limitations and non-claims

This release does not:

- certify an external implementation;
- create principal authority where governance does not provide it;
- treat a signature as sufficient authorization;
- define a threshold cryptosystem;
- make historical validity equivalent to current authorization;
- guarantee compatibility with unreviewed future TSMM/TIS state; or
- transfer semantic or portable-contract authority into TGA.

## Supersession

v0.12.1 remains immutable historical publication/provenance evidence. v0.13.0 supersedes it as the current TGA executable-governance release.
