# TGA v0.12.0 — Assurance Consolidation and Build Repair

## Release theme

Make the repository-wide assurance contract executable in CI and repair validation drift that prevented the current main branch from passing `make validate`.

## Build failures addressed

- `scripts/validate_tis_alignment.py` was pinned to TIS v0.12.0 while the reviewed binding targets TIS v0.14.1.
- `scripts/validate_repository_governance.py` still expected the retired flat `PROJECT-STATUS.yaml` shape after the repository migrated to the canonical nested portfolio schema.
- `VERSION` and `governance/repository-authority.yaml` remained at 0.5.0 while `PROJECT-STATUS.yaml` had advanced to 0.11.0.
- Pages relied on Bundler cache behavior without an explicit dependency installation step and did not execute the canonical repository assurance gate before publication.

## Assurance consolidation

- Add `scripts/validate_assurance_cases.py` to execute all `artifacts/*/tests/assurance-cases.yaml` suites.
- Add assurance-case execution to `scripts/validate_all.py`.
- Record the GitHub commit SHA in `artifacts/validation/latest.json` when validation runs in Actions.
- Report skipped checks when the full gate stops after a failed prerequisite.
- Replace package-only PR validation with `make validate`.
- Upload validation evidence from CI and Pages builds.
- Require a passing full assurance gate before Jekyll publication.

## Authority and compatibility

- Canonical semantic authority: TSMM v0.24.0.
- Portable contract authority: TIS v0.14.1.
- TGA v0.12.0 remains the executable-governance incubation, composition, and negative-assurance layer.

## Validation

```bash
python -m pip install jsonschema pyyaml
make validate
bundle install
bundle exec jekyll build
```

A release is acceptable only when the repository assurance gate passes and the Pages build completes against the same commit.
